# Function Calling（工具调用）实现要点

## 完整一轮的流程

第一步，请求时带上 tools 数组（每个工具含 name、description、parameters 的 JSON Schema），
以及 tool_choice 参数设为 auto，表示由模型自行决定是否调用。

第二步，模型如果决定调用工具，返回的 message 里会带 tool_calls 数组，
此时 content 通常为空。注意 tool_calls 里的 arguments 是 JSON 字符串，不是对象，需要手动解析。

第三步，本地执行工具函数，拿到结果。

第四步，把模型那条带 tool_calls 的 assistant 消息**原样追加**回消息列表，
再追加一条 role 为 tool 的消息，携带 tool_call_id 与执行结果。

第五步，再次请求模型，模型基于工具结果生成最终回答。

## 最容易错的一步

第三步之后，很多人会忘记把 assistant 的 tool_calls 消息追加回去，
只追加了 tool 消息。这样模型会报错，因为 tool 消息必须回应某个 tool_call_id，
找不到对应的调用就会被拒。

另一个常见错误是 tool_call_id 对不上，尤其是并行调用多个工具时。

## 多轮调用的上限

需要设置 MAX_ROUNDS，比如 5 轮。原因是模型可能陷入反复调用同一个工具的循环，
没有上限会一直烧钱。

## 并行与串行

模型可以在一次响应里返回多个 tool_calls，这叫并行调用。
但如果是串行依赖（比如先查订单状态、拿到订单号后再查物流），
模型会在第二轮才发起第二次调用。工具描述写得越清楚，模型越不容易搞错依赖顺序。
